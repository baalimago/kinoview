# Phase 6: Suggestion Cache

**Status:** ✅ Done (R1-02, R1-03 resolved Session 14)
[← README](./README.md)

## Goal

Skip the butler call entirely when neither the library nor the user's context has changed
since the last run.

**Depends on Phase 4** — the fingerprint is computed over `projectItems`, which Phase 4
introduces. Starting this first means fingerprinting fields the butler does not read, which
would invalidate the cache on every irrelevant metadata edit.

## Prerequisite: deterministic item ordering

Implement this first. Without it the cache hit rate is exactly 0%.

`store.Snapshot()` iterates a `map[string]model.Item`
([store.go:491-498](../../internal/media/storage/store.go:491)), so Go randomizes item order on
every call. A sha256 over the marshalled projection therefore differs on every call even when the
library is unchanged.

**Sort by `Path` inside `projectItems`.** Do not sort inside `Snapshot()` — that changes behaviour
for its other callers, which are outside this phase's scope. Record `Snapshot()`'s
nondeterminism as follow-up work.

Required test: `TestProjectItems_StableOrdering` — project a shuffled fixture 100 times, assert
byte-identical output. Fixtures for the other tests in this phase must be shuffled, not
pre-sorted.

## Specification

### The observation

Suggestions are a pure function of (library contents, watch history). A user who opens the
gallery, browses, and closes without playing anything makes the butler answer the same question
twice, at ~137K prompt tokens each.

### Fingerprint

```go
// suggestionFingerprint identifies the inputs a butler answer depends on.
type suggestionFingerprint struct {
    Library string `json:"library"` // sha256 over the marshalled []butlerItemView
    Context string `json:"context"` // sha256 over the fields below
    Version int    `json:"version"` // bump to invalidate all caches on a prompt/schema change
}
```

**Library component:** hash `projectItems(items)` marshalled — exactly the bytes the butler
would receive. This is the whole point of the Phase 4 dependency: a corrected plot summary
changes `model.Item` but not `butlerItemView`, and must not evict the cache.

**Context component:** hash a deliberate subset of `model.ClientContext`
([item.go:85-90](../../internal/model/item.go:85)) — **not** the whole struct:

| Field            | In hash? | Why                                                                     |
| ---------------- | -------- | ----------------------------------------------------------------------- |
| `LastPlayedName` | yes      | The single strongest signal for hints 1 and 2                            |
| `ViewingHistory` | yes, digested | See below                                                          |
| `SessionID`      | **no**   | Changes every reconnect; hashing it makes the cache never hit            |
| `StartTime`      | **no**   | Same problem                                                            |

`ViewingHistory` is digested rather than hashed raw: `(item name, coarse progress bucket)`
per entry, where progress is bucketed to 10-minute absolute steps. Watching 3 more
minutes of any item should not invalidate a suggestion set; crossing a 10-minute
boundary (e.g., 9:59 → 10:00) should. The 10%-of-total-duration metric described in
the original analysis is unachievable without the item’s total runtime, which
`ViewMetadata.PlayedForSec` does not carry.

**Day-of-week and time-of-day:** the butler's hint 4 explicitly reasons about weekly trends,
so a cached answer from Thursday is genuinely wrong on Friday. Include a `day-of-week` bucket
and a coarse `part-of-day` bucket (morning / afternoon / evening / night) in the context hash.
This is what makes the TTL below a safety net rather than the primary invalidator.

**`Version`:** a package constant bumped whenever the picker system prompt, the response
schema, or `butlerItemView` changes. Without it, Phases 2/3/4 landing after a deploy would
serve answers generated by an older prompt. Phase 2 and Phase 4 each bump it.

### Storage

Extend `suggestions.json` rather than adding a file — one artifact, one atomic write:

```json
{
  "suggestions": [ ... ],
  "fingerprint": { "library": "...", "context": "...", "version": 3 },
  "generated": "2026-07-25T14:02:11Z"
}
```

**Backward compatibility is required.** `Manager.load` currently reads a bare
`[]model.Suggestion` ([manager.go:76](../../internal/media/suggestions/manager.go:76)). It must
accept both shapes: a top-level array (legacy — load suggestions, treat fingerprint as absent,
so the next run is a miss) and the object form. Production has a live `suggestions.json`; a
failed load means the user's shelf empties on upgrade.

### Cache check

In the cascade, before calling the butler:

1. Compute the fingerprint.
2. On match, and `time.Since(generated) < butlerCacheTTL` (default **6 hours**), log a hit and
   return without an LLM call.
3. On miss, run the butler and store the new fingerprint with the result.

TTL default aligns with the concierge interval so the two agents' notions of freshness agree.
Configurable as `-butlerCacheTTL`; `0` disables caching.

**Only cache successful, non-empty results.** Caching an empty or partial result would pin a
broken shelf for six hours — the exact failure mode Phase 8 exists to eliminate.

### Hit rate

Not projected. Measure it with `kinoview llm usage` and record it in Implementation notes. Under
~20%, recommend reverting the phase rather than carrying the state.

## Integration contract

| # | Trigger                                                       | Collaborators              | Observable result                            | Required side effect                | Prohibited                                     |
| - | ------------------------------------------------------------- | -------------------------- | -------------------------------------------- | ----------------------------------- | ---------------------------------------------- |
| 1 | Two cascades, identical library and context, within TTL         | fake butler counting calls | **1** butler call; second serves the cache    | hit logged                          | No second LLM call                             |
| 2 | Second cascade after one new item is added                      | fake store                 | 2 butler calls                                | fingerprint updated                 | Cache must not mask a library change           |
| 3 | Second cascade after the user finishes an episode                | modified client context    | 2 butler calls                                | fingerprint updated                 | Cache must not mask a watch-state change       |
| 4 | Second cascade after only `SessionID` changes                    | new session, same history  | **1** butler call                             | hit logged                          | Reconnects must not evict                      |
| 5 | Second cascade after 3 more minutes, same bucket          | progress 5m → 8m          | **1** butler call                             | hit logged                          | Sub-bucket progress must not evict             |
| 6 | Second cascade after progress crosses 10-min boundary     | progress 9:59 → 10:00     | 2 butler calls                                | fingerprint updated                 | Bucket crossing must evict                     |
| 7 | Second cascade the next calendar day                            | fake clock +1 day           | 2 butler calls                                | fingerprint updated                 | Day-of-week must be part of the key            |
| 8 | Cached entry older than TTL                                     | fake clock                 | 2 butler calls                                | none                                | Stale entry must not be served                 |
| 9 | `Version` constant bumped between runs                          | fixture                    | 2 butler calls                                | none                                | Old-prompt answers must not survive a deploy   |
| 10 | Legacy bare-array `suggestions.json` on disk                    | legacy fixture             | Suggestions load; first cascade is a miss      | file rewritten in object form        | **No loss of existing suggestions**            |
| 11 | Butler returns zero suggestions                                 | fake butler                | Nothing cached                                | none                                | Must not pin an empty shelf for the TTL        |
| 12 | Corrupt `suggestions.json`                                      | corrupt fixture            | Warning; empty shelf; cascade proceeds         | file replaced on next success        | No startup failure                             |

## Acceptance criteria

- [ ] Identical inputs within TTL take zero butler calls — test: `TestCascade_CacheHit`
- [ ] Library change, watch-state change, day change, TTL expiry and version bump each evict — tests: `TestFingerprint_LibraryChange`, `_ContextChange`, `_DayOfWeek`, `TestCascade_TTLExpiry`, `TestFingerprint_VersionBump`
- [ ] `SessionID` and `StartTime` are excluded from the hash — test: `TestFingerprint_IgnoresSessionIdentity`
- [ ] Progress bucketing evicts on bucket crossing only — tests: `TestFingerprint_ProgressWithinBucket`, `TestFingerprint_ProgressCrossesBucket`
- [ ] **Item ordering is deterministic (prerequisite)** — test: `TestProjectItems_StableOrdering` (100 shuffles, byte-identical output). Without this the cache hit rate is 0%.
- [ ] Fingerprint survives a `Snapshot()` reorder — test: `TestFingerprint_StableAcrossSnapshotOrder` (same items, shuffled, assert identical fingerprint)
- [ ] Fingerprint is computed over `butlerItemView`, not `model.Item` — test: `TestFingerprint_IgnoresUnsentMetadata` (edit a plot summary, assert a hit)
- [ ] Legacy bare-array `suggestions.json` loads without losing suggestions — test: `TestManager_LoadLegacyArrayFormat`
- [ ] Round-trip of the object format preserves suggestions and fingerprint — test: `TestManager_RoundTripWithFingerprint`
- [ ] Empty and error results are never cached — tests: `TestCascade_DoesNotCacheEmpty`, `TestCascade_DoesNotCacheError`
- [ ] `-butlerCacheTTL 0` disables caching — test: `TestCascade_CacheDisabled`
- [ ] `-butlerCacheTTL` documented in `serve.go` flag help and `README.md`
- [ ] Real hit rate from one week on rpie recorded in Implementation notes, with a keep-or-revert recommendation

### Findings

- [x] **R1-02 (MODERATE): Fingerprint computation drifts from spec.** FIXED in session 14. `computeLibraryFingerprint` now uses `json.Marshal(butler.ProjectItems(items))` instead of field-by-field `Fprintf` hash. The `Index` field is zeroed before marshalling — it’s a transport artifact reflecting input order, not library content. This approach guards against struct drift: adding a field to `butlerItemView` automatically invalidates the cache without needing a corresponding line in the fingerprint function.

- [x] **R1-03 (MODERATE): Progress bucketing uses absolute 10-min buckets, not 10% steps.** FIXED in session 14. The spec table, integration contract rows 5-6, and the specification prose all updated to “10-minute absolute buckets” with a data-constraint note explaining that `ViewMetadata.PlayedForSec` does not carry total runtime, making percentage-based bucketing impossible.
